# Протокол CyberCord

CyberCord — сеть без серверов. Каждый запущенный клиент является полноценной нодой:
он хранит свои чаты, помогает другим соединяться (relay), раздаёт файлы и участвует
в DHT. Этот документ описывает, как устроена сеть в версии 0.9.

![Как ноды находят друг друга](img/guide-1-network.svg)

## 1. Транспорт и идентичность

| Слой | Что используется |
|---|---|
| Идентичность | ключ Ed25519, ID = libp2p PeerId (`12D3Koo…`), файл `identity.key` в папке данных |
| Транспорт | QUIC (UDP) и TCP, порт по умолчанию **47100**, при занятом порте — случайный |
| Шифрование соединения | Noise (TCP) / TLS 1.3 (QUIC) |
| Мультиплексирование | yamux |
| Рассылка | gossipsub (подписанные сообщения, `ValidationMode::Strict`, до 1 МБ) |
| Поиск нод и имён | Kademlia, протокол `/cybercord/kad/1.0.0`, режим сервера |
| За NAT | Circuit Relay v2 (каждая нода — relay, лимит 30 мин / 64 МБ на цепь), DCUtR (hole punching), UPnP |
| Локальная сеть | mDNS |

Дедупликация gossipsub — по хэшу содержимого сообщения. Поэтому все сообщения,
которые могут повторяться (запросы истории, запросы файлов, ответы с историей),
несут случайный `nonce` — иначе повтор отбрасывался бы как дубликат.

## 2. Как нода находит других (без сканирования)

CyberCord **не перебирает IP-адреса в интернете**. Подключение идёт только к
адресам, которые ноды сами о себе объявили:

1. **mDNS** — ноды в одной Wi-Fi/LAN.
2. **Сохранённые ноды** — `peers.json`, до 500 записей, при старте дозвон по свежести.
3. **Друзья** — адреса из кода подключения (`/ip4/…/p2p/<ID>`) или поиск по ID в DHT.
4. **Обмен списками (PEX)** — каждые 15 с нода публикует в `cc/control` себя и до 24
   самых свежих известных нод.
5. **Kademlia DHT** — `get_closest_peers` для поиска по ID, bootstrap раз в минуту.
6. **Глобальная точка встречи — Mainline DHT (BitTorrent).**
   Ключ: первые 20 байт `BLAKE3("cybercord/rendezvous/v1")`.
   * Нода, до которой можно достучаться (публичный IP или UPnP), делает
     `announce_peer(key, quic_port)`.
   * Все ноды делают `get_peers(key)` и дозваниваются до найденных
     (`/ip4/<ip>/udp/<port>/quic-v1`), не больше 16 за раунд, один адрес — не чаще раза в час.
   * Если никого нет — повтор через 10 с, 20 с, 40 с … до 5 мин; если нашли — раз в 15 мин.
   * Отключается в Настройки → Приватность (`"global": false`).
7. **Relay + hole punching** — ноды за NAT получают резервацию у доступной ноды
   другого пользователя, затем DCUtR пробует прямое соединение.

Цель — 8 соединений; дозвон до 5 новых нод за раунд.

## 3. Темы gossipsub

| Тема | Назначение |
|---|---|
| `cc/control` | пульс нод (`Score`), обмен списками (`Peers`) |
| `cc/ch/<сервер>/<канал>` | текстовый канал |
| `cc/dm/<ID_a>/<ID_b>` | личка (ID упорядочены, тема одинакова у обоих) |
| `cc/voice/<сервер>/<комната>` | голосовой канал |
| `cc/voice/cc/dm/…` | личный звонок |

## 4. Сообщения (`Wire`, JSON)

| Тип | Поля | Зачем |
|---|---|---|
| `Chat` | `ChatEvent {id, channel, name, body, ts_ms, attach?}` | сообщение |
| `History` | `ev, nonce` | ответ на запрос истории |
| `SyncReq` | `channel, since_ms, nonce` | «пришлите, что было после…» (ответ — до 50 сообщений) |
| `Score` | `peer, name, score, ts_ms, reachable, voice?, listed` | пульс раз в 5 с: выбор хаба, присутствие, кто в каком голосовом канале, каталог имён |
| `Peers` | список `PeerRec {peer, addrs, last_seen_ms}` | обмен списками нод |
| `Voice` | `room, name, seq, pcm` | 20 мс голоса, 48 кГц моно i16 |
| `BlobChunk` | `hash, idx, total, round, data(base64)` | кусок файла (192 КБ) |
| `BlobReq` | `hash, nonce` | «у кого есть этот файл?» |

## 5. История чатов

* Каждое сообщение сохраняется у каждого получателя (`channels/<сервер>__<канал>.jsonl`).
* При открытии канала и при появлении нового участника комнаты нода отправляет
  `SyncReq` с временем последнего известного сообщения; участники отвечают `History`.
* Отдельно каждые 5 с проверяется, с кем в открытых комнатах ещё не синхронизировались.

## 6. Файлы, GIF, кружки, музыка, голосовые

* Файл адресуется по `BLAKE3` от содержимого, лимит 16 МБ.
* Отправитель публикует куски в тему канала; получатель собирает, проверяет хэш, сохраняет в `blobs/`.
* Чего не хватает — запрашивается `BlobReq` до 6 раз; отвечает любой, у кого файл есть
  (не чаще раза в 4 с на файл и раза в 15 с одной и той же ноде).
* Поэтому файл доступен, даже когда автор офлайн.

| Вид | Формат |
|---|---|
| GIF / картинка | как есть (GIF, PNG, JPEG) |
| Видео-кружок | JSON: кадры JPEG 240×240 @15 к/с + PCM-звук |
| Музыка | mp3 / flac / ogg (Vorbis) / wav / m4a (AAC), декодируется symphonia |
| Голосовое | WAV 16 кГц моно, имя `voice-message.wav`, до 5 мин |

## 7. Голос

* Захват с выбранного устройства → громкость ввода → шумовой порог
  (авто: следует за фоном, ×3.5, −48…−24 дБ; вручную: −100…0 дБ, удержание 300 мс)
  → ресемплинг в 48 кГц → кадры по 20 мс.
* Приём: очередь до 2 с → ресемплинг в частоту устройства → громкость вывода.
* Кто в какой комнате, видно из поля `voice` в пульсе (личные звонки не объявляются).

## 8. Хаб (виртуальный центральный узел)

Сервера нет, но для координации выбирается «хаб» — самая подходящая нода из живых:

```
score = 0.35·доступен_из_интернета + 0.30·min(аптайм/30 мин, 1)
      + 0.25·min(соединения/8, 1) + 0.10·стабильная_случайность(ID)
```

Хаб и резерв видны всем одинаково (детерминированный выбор по пульсу).

## 9. Поиск людей и карта сети

* **Каталог** — имена из пульса (`listed = true`), сохраняются в `directory.json`
  (до 5000 записей), поэтому находятся и офлайн-пользователи.
* **Индекс имён в Kademlia** — нода с `listed = true` объявляет себя провайдером ключей
  `BLAKE3("cybercord/name/v1/" + префикс)` для каждого префикса имени длиной 3…24
  и для каждого слова имени. Поиск = подстрока по каталогу + `get_providers(префикс)`;
  найденные через DHT ноды получают дозвон (до 8), и их пульс приносит имя.
* **Карта** — снимок адресной книги раз в 1,5 с: соединён ли, тип соединения
  (`lan`/`direct`/`relay`), откуда узнали (`lan`, `saved`, `friend`, `node`, `global`,
  `exchange`, `dht`, `search`, `identify`), relay в какую сторону, в сети ли.

## 10. Безопасность — честно

* Соединения шифруются (Noise/TLS). Relay пересылает только зашифрованные байты.
* **Сообщения в личках не шифруются сквозным ключом друзей.** Нода, знающая оба ID,
  может подписаться на тему лички. Сквозное шифрование (MLS) — следующий шаг.
* Сообщения gossipsub подписаны ключом автора: подделать чужое сообщение нельзя.
* Включённый глобальный поиск раскрывает участникам DHT BitTorrent, что ваш IP
  пользуется CyberCord.
